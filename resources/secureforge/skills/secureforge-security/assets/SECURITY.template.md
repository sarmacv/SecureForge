# Security policy

## Supported versions

Document the versions or branches that currently receive security updates.

## Reporting a vulnerability

Do not report suspected vulnerabilities in a public issue. Use the repository's
private vulnerability reporting feature or the approved private security
contact.

Include reproduction steps, affected components, potential impact, and any
known mitigations. Do not include production credentials, customer data, or
other secrets in the report.

## Response expectations

Document acknowledgment, assessment, remediation, and coordinated-disclosure
expectations appropriate for this project.
